# OS별 모바일 네비게이션 스위칭 방향

모바일 하단 네비게이션을 iOS/Android 구분 없이 캡슐(pill) 독 하나로 통일해 쓰던 상태에서, iOS 전용 디자인을 Android에 그대로 노출하는 문제 정리. 현재 캡슐 독 스펙은 [`capsule-dock-spec.md`](./capsule-dock-spec.md) 참고. 2026-09-10 기준 논의안이며 구현 전 단계.

## 배경

- 캡슐(플로팅 pill) 독은 iOS 홈 인디케이터/다이나믹 아일랜드 미감 기준으로 설계됨
- Android 실기기 보유 없음 — 개발 중 UA(User Agent) 감지와 데모 방식을 함께 정해야 실제 확인 가능

## 전환 기준

1순위: `navigator.userAgent` 판별
- iOS: `/iPhone|iPad|iPod/i` 매치 시 캡슐 독
- Android: `/Android/i` 매치 시 Android용 네비게이션 바
- UA는 조작 가능한 값이나, OS별 네이티브 감 UI 분기 용도로는 충분

2순위: 위 매치가 둘 다 실패하는 환경(데스크톱 UA로 반응형만 축소한 경우 등)
- 기본값은 캡슐 독 유지 (현재 사용자 환경 기준)

개발/데모 전용 오버라이드
- `?os=android` / `?os=ios` 쿼리 파라미터, 또는 `localStorage`(`veloo:os-override`) 값이 있으면 UA 무시하고 강제 전환
- 실기기 없이도 코드 레벨에서 즉시 스위칭 확인 가능하도록 필수로 넣을 항목

## 데모(개발자도구) 방법

크롬 개발자도구 기기 툴바(Ctrl+Shift+M)에서 **구체적 기기 프리셋 선택**이 조건.

- "Responsive" 모드로 자유 리사이즈만 하면 화면 크기만 바뀌고 UA는 데스크톱 크롬 그대로 유지됨 — 전환 로직이 걸리지 않음
- 상단 드롭다운에서 실제 기기(iPhone 14 Pro Max 등)를 선택하면 `navigator.userAgent`가 선택한 기기 값으로 바뀌어 전송됨 — 기기 프리셋 선택 시에만 UA 감지 데모 가능
- 크롬 기본 프리셋에 Android 기기(Pixel 7, Galaxy S20 Ultra 등)가 포함되어 있어 실기기 없이도 UA 기준 전환 확인 가능

## Android 네비게이션 방향

Material 3 Expressive 가이드라인(2025~2026 기준) 참고.

- 완전 플로팅 캡슐 형태가 아니라 **하단 고정 바(container) + 아이콘/라벨**
- 선택된 항목에는 알약형(pill) 하이라이트 적용 — 독 전체가 뜨는 게 아니라 항목 배경만 강조
- 일부 제조사(삼성 One UI)는 하단 고정 바 + 리플 효과 선호, 플로팅 방식은 드묾

결론: iOS는 플로팅 캡슐 독 유지, Android는 하단 고정 바 + 선택 항목 pill 하이라이트 조합.

## 구현 방향(요약)

- `useDeviceOS()` 훅 신설 — UA 판별 + 오버라이드 값 우선 적용
- `Shell.tsx`에서 기존 캡슐 독 컴포넌트는 그대로 두고, Android용 네비게이션 바 컴포넌트를 별도 추가해 훅 결과로 분기 렌더
- 사용자 확인 필요: Android 네비게이션 바의 구체적 색상/치수는 착수 전 별도 협의
