# 기능 상세

README에서 옮겨온 5개 모듈의 상세 설명. 각 모듈은 독립적으로도 쓸 수 있지만,
같은 계정·같은 히스토리를 공유하는 하나의 워크스페이스 안에 있다는 전제로
설계되어 있음.

## Paper Analyzer — 논문 분석

**필요성**
논문을 다 읽고 나서야 venue의 신뢰도와 결과의 중요성을 알게 되는 경우가
많음. 읽기 전에 거를 기준이 없으면 시간 손실이 큼.

**동작**
- PDF 업로드 또는 제목·URL 검색으로 논문 입력.
- Semantic Scholar API 연동으로 메타데이터·저자 정보 자동 채움.
- Claude가 논문의 문제 정의–방법론–결론을 구조화하여 요약.
- 내장된 SJR(SCImago Journal Rank) 데이터셋으로 게재 venue의 저널 품질
  점수 함께 제공.

**사용 방법**
1. 논문 PDF 업로드 또는 제목 검색.
2. 메타데이터·저자·venue 품질 점수 자동 채움.
3. AI 요약(문제–방법–결론)을 먼저 훑어보고 전체를 읽을지 판단.
4. 읽다가 막히는 용어나 문장은 Concepts·Trans 모듈로 바로 넘어가 확인.

**기대 효과**
읽기 전에 시간을 투자할 가치가 있는 논문인지 사전 판단이 가능해지고, 약한
venue 논문에 낭비되는 시간이 줄어듦.

## Translator — 번역

**필요성**
일반 번역기(Google/DeepL 등)는 도메인 지식이 없어 수식, 고유명사,
ML(Machine Learning)/DL(Deep Learning) 전문용어를 문맥 없이 직역해버려
오히려 이해를 방해하는 경우가 많음.

**동작**
- 영어 > 한국어 스트리밍 번역(문장 단위로 실시간 출력).
- ML/DL/CV(Computer Vision)/NLP(Natural Language Processing) 분야에 특화
  튜닝: 수식·고유명사는 원문 그대로 두고, 직역 시 혼란을 주는 전문용어는
  영어 그대로 유지.

**사용 방법**
1. Paper 모듈에서 읽던 논문 중 이해가 안 되는 문단을 복사해 Trans에
   붙여넣기.
2. 스트리밍으로 번역 결과를 확인하면서 원문과 대조.
3. 번역 중에도 등장하는 전문용어는 Concepts 모듈에서 추가로 맥락 확인.

**기대 효과**
일반 번역기 대비 연구 문서 특화 정확도를 확보하고, 영어 논문 독해 속도와
이해도가 향상됨.

## Contextor — 용어 맥락 정리

**필요성**
같은 용어라도 논문(서브필드)마다 다른 의미로 쓰이는 경우가 많음(예: 하나의
단어가 CV 논문과 NLP 논문에서 다른 개념을 지칭). 일반 사전이나 위키는
맥락별 의미 차이를 반영하지 못하고 단일 정의만 제공.

**동작**
- 영어 단어/짧은 구문을 입력하면, ML/DL 여러 맥락에서 실제로 어떻게
  쓰이는지 구조화된 형태로 반환.
- 하나의 정의로 뭉뚱그리지 않고, 맥락별 의미를 분리해서 제공.

**사용 방법**
1. 논문을 읽거나 번역하다가 정확한 뜻이 궁금한 단어를 Concepts에 입력.
2. 맥락별로 분리된 의미 목록에서 읽고 있는 논문의 분야에 맞는 의미 확인.
3. 뜻이 불분명했던 용어는 이후 검색 기록으로 남아 반복 확인이 쉬움.

**기대 효과**
반쯤만 이해하고 넘어가는 용어를 줄이고, 분야를 넘나들며 논문을 읽을 때
발생하는 개념 혼동을 줄임.

## Model Review — 아키텍처 학습 & 자가 검증

**필요성**
아키텍처 다이어그램은 눈으로 훑어보는 것과 실제로 설명할 수 있는 것 사이에
큰 차이가 있음. 대부분의 학습 도구는 "봤다"에서 멈추고, 실제 이해 여부를
검증할 수단은 제공하지 않음.

**동작**
- 아키텍처 다이어그램(이미지)을 업로드하면 AI가 구성 요소 간 연결 관계의
  레퍼런스 설명 생성.
- 사용자가 직접 자기 언어로 다이어그램을 설명하는 글을 작성하면, AI가 이를
  레퍼런스 설명과 비교해 채점하고 교정.

**사용 방법**
1. 논문에서 나온 모델 아키텍처 그림을 캡처해 업로드.
2. AI 레퍼런스 설명을 먼저 읽지 않고, 본인이 이해한 대로 먼저 설명을
   작성(액티브 리콜).
3. 제출 후 AI 채점·교정 결과를 받아 본인 이해와 실제 구조의 차이 확인.
4. 틀린 내용은 Concepts·Paper 모듈로 돌아가 다시 확인.

**기대 효과**
다이어그램을 "본 것"이 아니라 "설명할 수 있는 것"으로 전환하고, 셀프 퀴즈
루프로 장기 기억을 정착시킴.

## Plan (Todo + Calendar) — 실행 관리

**필요성**
논문을 읽고 새로운 개념을 배워도, 배운 내용이 실제 연구 진행(실험, 다음
논문, 미팅 준비 등)으로 이어지지 않으면 "읽었다"에서 끝남. 별도의 할 일
관리 앱을 쓰면 방금 읽은 맥락이 끊긴 채로 새 태스크를 만들어야 함.

**동작**
- 하위 단계·우선순위가 있는 연구 태스크 관리.
- AI 기반 태스크 분해(breakdown) 및 진행 전략 제안.
- 드래그 앤 드롭 방식의 주간 타임블로킹 캘린더 및 리뷰 기능.

**사용 방법**
1. Paper/Models 모듈에서 읽거나 학습한 내용 중 후속 조치가 필요한 항목을
   Plan으로 이관.
2. AI가 제안하는 하위 단계 분해를 참고해 태스크 구체화.
3. 주간 캘린더에 드래그 앤 드롭으로 시간 배정.
4. 주 단위로 리뷰하며 다음 주 계획에 반영.

**기대 효과**
읽은 논문이 실행되는 작업으로 자연스럽게 전환되고, 열어둔 탭으로 흩어져
있던 후속 작업의 유실을 막음.
