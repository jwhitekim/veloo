# Veloo 제안서 (Why / What Changes / Impact)

## Why

연구를 진행할 때 대학원생·연구자는 PDF 리더, 번역기, 용어 검색, 노트/암기 앱, 할 일 관리/캘린더를 오간다. 문제는 각 도구가 서로의 맥락을 전혀 공유하지 못한다는 점이다 — 논문을 읽다가 번역기로 넘어가면 방금까지 읽던 문맥을 다시 설명해야 하고, 용어를 찾아봐도 그 결과가 할 일 관리로 이어지지 않는다. 도구를 전환할 때마다 지금 하던 작업을 새로 복원해야 하는 비용이 반복적으로 발생한다.

기존 개별 도구의 한계:
- **번역기**: ML/DL/CV/NLP 분야의 수식·고유명사·전문용어를 문맥 없이 직역해 오히려 이해를 방해.
- **논문 관리 툴**: venue(저널/학회)의 질적 수준을 사전에 판단할 근거를 주지 않음.
- **용어 사전**: 하나의 용어가 논문마다 다른 의미로 쓰이는 경우를 반영하지 못하고 단일 정의만 제공.
- **다이어그램 학습**: 아키텍처 다이어그램을 눈으로 훑고 넘어가는 데 그치며, 실제로 이해했는지 검증할 방법이 없음.

## What Changes

승인된 계정마다 `/:username` 개인 워크스페이스를 제공하고, 아래 6개 capability를 하나의 로그인·하나의 히스토리 아래로 묶는다.

| capability | 한 줄 요약 |
|---|---|
| auth | 회원가입·로그인·세션 미들웨어 — 나머지 전부가 의존하는 계층 |
| paper-analyzer | 논문 업로드/검색 > AI 요약 + SJR 저널 품질 점수로 읽기 전 사전 판단 |
| translator | ML/DL/CV/NLP 특화 영→한 스트리밍 번역 |
| contextor | 용어를 논문/분야별 맥락으로 분리해서 구조화된 의미 제공 |
| model-review | 아키텍처 그림을 직접 설명 > AI 레퍼런스와 비교 채점 |
| todo | AI 단계 분해 + 드래그 앤 드롭 주간 타임블로킹, 마감일 리마인드 |
| product | 화면 구조·정보 위계·완료 기준 등 capability를 가로지르는 제품 원칙(FROZEN, `contract.md`) |
| mobile-navigation | iOS 캡슐 독 / Android 하단 바 — 위 backend capability들이 존재한다는 전제로 화면을 조립 |

## Impact

- 한 모듈에서 만든 맥락(읽은 논문, 찾아본 용어 등)이 다른 모듈로 이어질 수 있는 구조 — 도구 전환 비용 자체를 없앰
- 개인 배포판(veloo.2joon.com, 프라이빗 베타·가입 승인제)이며 공유 랩 도구가 아님
